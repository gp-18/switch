## 1. Library Book Management System (`Book`)

You are tasked to design a class `Book` to manage book inventory in a library. The class must protect internal availability records from arbitrary modification while exposing a controlled public interface.

### Specifications

* **Attributes:**
  * `title (list[str])`: The titles of the books in the library (**public**).
  * `author (list[str])`: The authors of the corresponding books (**public**).
  * `__isAvailable (list[bool])`: The availability status of each book (**private**).
* **Methods:**
  * `__init__(self, title, author, isAvailable)`: Parameterized constructor initializing the three parallel lists.
  * `borrowBook(self, bookName: str)`: Searches for `bookName`.
    * If available (`True`), borrow the book and mark its status as `False`.
    * If already borrowed (`False`), print `"Book is not available."`.
    * If the book is not found in the catalog, print `"Book not found."`.
  * `returnBook(self, bookName: str)`: Searches for `bookName` and marks its available flag as `True`.
  * `getAvailability(self, bookName: str)`: Prints `True` if available, or `False` if unavailable. If not found, prints `"Book not found."`.

### Operation Codes
* `"1 <bookName>"` $\rightarrow$ calls `borrowBook(bookName)`
* `"2 <bookName>"` $\rightarrow$ calls `returnBook(bookName)`
* `"3 <bookName>"` $\rightarrow$ calls `getAvailability(bookName)`

### Example

```text
Input:
title = ["Sherlock_Holmes", "Frankenstein", "King_Arthur", "Treasure_Island"]
author = ["Arthur_Conan_Doyle", "Mary_Shelley", "Roger_Lancelyn_Green", "Robert_Louis_Stevenson"]
isAvailable = [False, True, False, False]
methodCalls = [
    ["1", "Frankenstein"],
    ["1", "Sherlock_Holmes"],
    ["2", "King_Arthur"],
    ["3", "Sherlock_Holmes"],
    ["1", "Frankenstein"]
]

Output:
Book is not available.
False
Book is not available.

Explanation:
1. borrowBook("Frankenstein"): Available (True) -> Marked as False.
2. borrowBook("Sherlock_Holmes"): Already unavailable -> Prints "Book is not available.".
3. returnBook("King_Arthur"): Marked as True.
4. getAvailability("Sherlock_Holmes"): Prints False.
5. borrowBook("Frankenstein"): Was borrowed in step 1, now unavailable -> Prints "Book is not available.".
```

### Think About

* `__isAvailable` is marked private with double leading underscores so that external callers cannot arbitrarily manipulate stock status without going through `borrowBook` or `returnBook`.
* Map book names to index positions: `idx = self.title.index(bookName)` to look up or update the corresponding element in `self.__isAvailable`.
* Handle `ValueError` gracefully if the book does not exist in `self.title`.
* **Time Complexity:** $\mathcal{O}(N)$ per lookup/operation where $N$ is the number of books in catalog.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space beyond storing the initial lists.

## 2. Bank Account with Audit Log (`BankAccount`)

Design a `BankAccount` class where the monetary balance and transaction history cannot be directly altered from outside, preventing balance tampering and maintaining a reliable audit trail.

### Specifications

* **Attributes:**
  * `account_number (str)`: Unique account number (**public**).
  * `holder_name (str)`: Account holder's name (**public**).
  * `__balance (float)`: The current account balance (**private**).
  * `__transactions (list[str])`: History log of all completed transactions (**private**).
* **Methods:**
  * `__init__(self, account_number: str, holder_name: str, initial_balance: float)`: Initializes attributes. If `initial_balance < 0`, sets `__balance = 0.0`.
  * `deposit(self, amount: float)`: If `amount > 0`, adds `amount` to `__balance` and logs `"Deposited: ${amount:.2f}"`. Otherwise prints `"Invalid deposit amount."`.
  * `withdraw(self, amount: float)`: If `0 < amount <= __balance`, deducts `amount` and logs `"Withdrew: ${amount:.2f}"`. If `amount > __balance`, prints `"Insufficient funds."`. If `amount <= 0`, prints `"Invalid withdrawal amount."`.
  * `get_balance(self) -> float`: Returns the current balance.
  * `get_statement(self) -> list[str]`: Returns a copy of the transaction history list.

### Example

```text
Input:
account = BankAccount("ACC101", "Alice", 1000.0)
account.deposit(500.0)
account.withdraw(200.0)
account.withdraw(2000.0)
print(account.get_balance())
print(account.get_statement())

Output:
Insufficient funds.
1300.0
['Deposited: $500.00', 'Withdrew: $200.00']
```

### Think About

* The internal `__balance` and `__transactions` lists are encapsulated. Outside code cannot directly append fraudulent transactions or modify the balance without executing validation logic.
* `get_statement()` should return `self.__transactions.copy()` to avoid exposing the internal mutable list reference.
* **Time Complexity:** $\mathcal{O}(1)$ per deposit, withdrawal, or balance lookup.
* **Space Complexity:** $\mathcal{O}(T)$ where $T$ is the number of recorded transactions.

## 3. Student Academic Grade Tracker (`Student`)

Design a `Student` class to track subject grades. Grades must be validated strictly between 0 and 100 before being accepted into the student's record.

### Specifications

* **Attributes:**
  * `student_id (str)`: Unique student identifier (**public**).
  * `name (str)`: Student name (**public**).
  * `__grades (dict[str, float])`: Dictionary mapping subject name to grade score (**private**).
* **Methods:**
  * `__init__(self, student_id: str, name: str)`: Initializes student with an empty grades dictionary.
  * `add_grade(self, subject: str, score: float)`: If `0.0 <= score <= 100.0`, records `__grades[subject] = score`. Otherwise prints `"Invalid grade. Must be between 0 and 100."`.
  * `get_grade(self, subject: str) -> float | None`: Returns the score for `subject`, or `None` if the subject has not been graded.
  * `calculate_average(self) -> float`: Returns the average score across all graded subjects. Returns `0.0` if no grades exist.
  * `get_report_card(self) -> dict[str, float]`: Returns a copy of all recorded subject-grade pairs.

### Example

```text
Input:
student = Student("S101", "Rahul")
student.add_grade("Math", 95.0)
student.add_grade("Science", 88.0)
student.add_grade("History", 105.0)  # Invalid grade
print(student.calculate_average())
print(student.get_report_card())

Output:
Invalid grade. Must be between 0 and 100.
91.5
{'Math': 95.0, 'Science': 88.0}
```

### Think About

* Hiding `__grades` prevents external code from inserting corrupt values like negative numbers or scores over 100.
* Returning `self.__grades.copy()` preserves encapsulation against external dictionary mutations.
* **Time Complexity:** $\mathcal{O}(1)$ per grade insertion/lookup; $\mathcal{O}(K)$ for average calculation where $K$ is number of subjects.
* **Space Complexity:** $\mathcal{O}(K)$ memory.

## 4. Employee Salary & Performance Manager (`Employee`)

Design an `Employee` class where salary changes and performance bonuses require manager authorization and strict bounds.

### Specifications

* **Attributes:**
  * `emp_id (int)`: Employee ID (**public**).
  * `department (str)`: Employee department (**public**).
  * `__base_salary (float)`: Monthly base salary (**private**).
  * `__performance_rating (int)`: Integer rating from 1 to 5 (**private**).
* **Methods:**
  * `__init__(self, emp_id: int, department: str, base_salary: float, rating: int)`: Initializes employee. Base salary must be $\ge 0$ and rating must be in $[1, 5]$.
  * `update_salary(self, new_salary: float, is_manager: bool)`: Only updates `__base_salary` if `is_manager == True` and `new_salary >= self.__base_salary`. Otherwise prints `"Unauthorized or invalid salary update."`.
  * `set_rating(self, new_rating: int)`: Updates `__performance_rating` if $1 \le \text{new\_rating} \le 5$. Otherwise prints `"Rating must be between 1 and 5."`.
  * `calculate_bonus(self) -> float`:
    * Rating 5: 20% of base salary
    * Rating 4: 15% of base salary
    * Rating 3: 10% of base salary
    * Rating 1 or 2: 0% bonus
  * `get_total_compensation(self) -> float`: Returns `__base_salary + calculate_bonus()`.

### Example

```text
Input:
emp = Employee(1001, "Engineering", 80000.0, 4)
print("Bonus:", emp.calculate_bonus())
emp.update_salary(75000.0, is_manager=True)   # Attempt salary reduction
emp.update_salary(90000.0, is_manager=False)  # Unauthorized
emp.update_salary(95000.0, is_manager=True)   # Valid update
emp.set_rating(5)
print("Total Compensation:", emp.get_total_compensation())

Output:
Bonus: 12000.0
Unauthorized or invalid salary update.
Unauthorized or invalid salary update.
Total Compensation: 114000.0
```

### Think About

* Encapsulation ensures salary cannot be decremented or modified by unauthorized non-manager callers.
* Bonus calculation is isolated inside the class so corporate compensation logic can be refactored without breaking external client scripts.
* **Time Complexity:** $\mathcal{O}(1)$ for all operations.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 5. E-Commerce Product Inventory Controller (`Product`)

Design a `Product` class to manage warehouse stock. Stock quantity must never become negative, and sales must be rejected if demand exceeds availability.

### Specifications

* **Attributes:**
  * `product_id (str)`: Product SKU (**public**).
  * `product_name (str)`: Display title (**public**).
  * `price (float)`: Unit selling price (**public**).
  * `__stock_quantity (int)`: Available units in warehouse (**private**).
* **Methods:**
  * `__init__(self, product_id: str, product_name: str, price: float, initial_stock: int)`: Initializes attributes. If `initial_stock < 0`, sets `__stock_quantity = 0`.
  * `restock(self, count: int)`: Adds `count` to `__stock_quantity` if `count > 0`. Otherwise prints `"Restock count must be positive."`.
  * `purchase(self, count: int) -> float`:
    * If `count <= 0`, prints `"Invalid purchase quantity."` and returns `0.0`.
    * If `count > self.__stock_quantity`, prints `"Insufficient stock. Available: {self.__stock_quantity}"` and returns `0.0`.
    * Otherwise, deducts `count` from `__stock_quantity` and returns total cost `count * price`.
  * `get_stock(self) -> int`: Returns current available stock count.

### Example

```text
Input:
laptop = Product("P-501", "Gaming Laptop", 1200.0, 10)
print("Total Paid:", laptop.purchase(3))
print("Remaining Stock:", laptop.get_stock())
print("Total Paid:", laptop.purchase(10))  # Exceeds remaining stock (7)
laptop.restock(5)
print("Stock after restock:", laptop.get_stock())

Output:
Total Paid: 3600.0
Remaining Stock: 7
Insufficient stock. Available: 7
Total Paid: 0.0
Stock after restock: 12
```

### Think About

* Making `__stock_quantity` private guarantees that inventory cannot drop below zero due to concurrent or erroneous external writes.
* Financial calculations (`count * price`) only occur after validating stock sufficiency.
* **Time Complexity:** $\mathcal{O}(1)$ per transaction.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 6. Secure User Account & Password Lock (`UserAccount`)

Design a `UserAccount` class that encapsulates user authentication credentials, enforces minimum password standards, and automatically locks accounts after repeated failed login attempts.

### Specifications

* **Attributes:**
  * `username (str)`: Public username (**public**).
  * `email (str)`: Public email address (**public**).
  * `__password (str)`: Secret password string (**private**).
  * `__failed_attempts (int)`: Count of consecutive failed logins (**private**).
  * `__is_locked (bool)`: Flag indicating if the account is locked (**private**).
* **Methods:**
  * `__init__(self, username: str, email: str, password: str)`: Initializes account. Password must be at least 8 characters long.
  * `login(self, attempted_password: str) -> bool`:
    * If `__is_locked` is `True`, prints `"Account is locked. Contact administrator."` and returns `False`.
    * If `attempted_password == self.__password`, resets `__failed_attempts = 0` and returns `True`.
    * Otherwise, increments `__failed_attempts += 1`. If `__failed_attempts >= 3`, sets `__is_locked = True` and prints `"Account locked due to 3 failed attempts."`. Returns `False`.
  * `change_password(self, old_pwd: str, new_pwd: str) -> bool`:
    * Requires `old_pwd == self.__password`.
    * Requires `len(new_pwd) >= 8` and `new_pwd != old_pwd`.
    * If valid, updates `__password` and returns `True`. Otherwise prints `"Password change failed."` and returns `False`.
  * `unlock_account(self, admin_key: str) -> bool`: If `admin_key == "ADMIN_KEY_999"`, unlocks account and resets failed attempts.

### Example

```text
Input:
user = UserAccount("john_doe", "john@example.com", "Secret@123")
print("Login 1:", user.login("Wrong1"))
print("Login 2:", user.login("Wrong2"))
print("Login 3:", user.login("Wrong3"))  # Triggers lock
print("Login 4:", user.login("Secret@123"))  # Should fail because locked
user.unlock_account("ADMIN_KEY_999")
print("Login after unlock:", user.login("Secret@123"))

Output:
Login 1: False
Login 2: False
Account locked due to 3 failed attempts.
Login 3: False
Account is locked. Contact administrator.
Login 4: False
Login after unlock: True
```

### Think About

* Security policies (like account lockout thresholds and password complexity) are internal invariants that must never be exposed for external alteration.
* **Time Complexity:** $\mathcal{O}(1)$ for login and password verification.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 7. Smart Thermostat Temperature Limiter (`Thermostat`)

Design a `Thermostat` class that protects heating and cooling hardware by restricting user target temperatures to a safe operational envelope ($10.0^\circ C \le T \le 35.0^\circ C$).

### Specifications

* **Attributes:**
  * `device_id (str)`: Thermostat hardware ID (**public**).
  * `mode (str)`: Operational mode: `"OFF"`, `"HEAT"`, or `"COOL"` (**public**).
  * `__current_temp (float)`: Current ambient temperature reading from sensor (**private**).
  * `__target_temp (float)`: Desired temperature (**private**).
* **Methods:**
  * `__init__(self, device_id: str, ambient_temp: float)`: Sets `__current_temp` and initializes `__target_temp = 21.0` (standard room temperature).
  * `set_target_temp(self, temp: float)`: Validates that $10.0 \le \text{temp} \le 35.0$. If valid, updates `__target_temp`. Otherwise prints `"Temperature out of safe bounds (10.0C - 35.0C)."`.
  * `get_target_temp(self) -> float`: Returns `__target_temp`.
  * `update_sensor(self, sensor_temp: float)`: Simulates temperature sensor hardware updating `__current_temp`.
  * `get_status(self) -> str`: Returns formatted status string: `"Device: {device_id} | Mode: {mode} | Current: {current_temp}C | Target: {target_temp}C"`.

### Example

```text
Input:
t = Thermostat("NEST-001", 18.5)
t.mode = "HEAT"
t.set_target_temp(23.5)
t.set_target_temp(45.0)  # Unsafe extreme temperature
print(t.get_status())

Output:
Temperature out of safe bounds (10.0C - 35.0C).
Device: NEST-001 | Mode: HEAT | Current: 18.5C | Target: 23.5C
```

### Think About

* Encapsulating `__target_temp` prevents dangerous hardware extremes (like freezing pipes or burning heating coils).
* The sensor reading `__current_temp` can only be updated through dedicated hardware callbacks, preventing external tampering.
* **Time Complexity:** $\mathcal{O}(1)$ for all calls.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 8. Tamper-Proof Car Odometer & Dashboard (`CarDashboard`)

Design a `CarDashboard` class. In real vehicles, the odometer can **never** be rolled back (it must be strictly monotonic), and speed must never exceed vehicle physical limits or drop below zero.

### Specifications

* **Attributes:**
  * `vin (str)`: Vehicle Identification Number (**public**).
  * `model (str)`: Car model name (**public**).
  * `__odometer_km (float)`: Cumulative distance traveled (**private**).
  * `__speed_kmh (float)`: Current vehicle speed (**private**).
  * `__max_speed (float)`: Top speed limit for this model (**private**).
* **Methods:**
  * `__init__(self, vin: str, model: str, max_speed: float)`: Initializes odometer to `0.0`, speed to `0.0`, and max speed to `max_speed`.
  * `accelerate(self, amount: float)`: Increases speed by `amount` (if `amount > 0`), capping at `__max_speed`.
  * `brake(self, amount: float)`: Decreases speed by `amount` (if `amount > 0`), floored at `0.0`.
  * `drive(self, distance_km: float)`: If `distance_km > 0`, increases `__odometer_km` by `distance_km`. If `distance_km <= 0`, prints `"Invalid travel distance."`.
  * `get_odometer(self) -> float`: Returns total kilometers recorded.
  * `get_speed(self) -> float`: Returns current vehicle speed.

### Example

```text
Input:
car = CarDashboard("1HGCR2F83HA", "Sedan GT", 220.0)
car.accelerate(50.0)
car.accelerate(200.0)  # Should cap at max_speed (220.0)
print("Speed:", car.get_speed())
car.brake(100.0)
print("Braked Speed:", car.get_speed())
car.drive(150.5)
car.drive(-20.0)       # Tampering attempt (odometer roll-back)
print("Odometer Reading:", car.get_odometer())

Output:
Speed: 220.0
Braked Speed: 120.0
Invalid travel distance.
Odometer Reading: 150.5
```

### Think About

* **Odometer Monotonicity:** Hiding `__odometer_km` protects legal vehicle compliance; it is physically impossible to roll back mileage.
* Speed bounds $[0, \text{max\_speed}]$ are strictly maintained internally.
* **Time Complexity:** $\mathcal{O}(1)$ for all updates.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 9. Digital Wallet with Daily Spending Limit (`DigitalWallet`)

Design a `DigitalWallet` class that enforces both account balance checks and regulatory daily spending ceilings to protect against fraudulent drains.

### Specifications

* **Attributes:**
  * `wallet_id (str)`: Wallet account ID (**public**).
  * `owner (str)`: Owner name (**public**).
  * `__balance (float)`: Available funds (**private**).
  * `__daily_limit (float)`: Maximum spending allowed per calendar day (**private**).
  * `__spent_today (float)`: Total expenditures accumulated today (**private**).
* **Methods:**
  * `__init__(self, wallet_id: str, owner: str, initial_balance: float, daily_limit: float)`: Initializes wallet state.
  * `top_up(self, amount: float)`: Adds `amount` to `__balance` if `amount > 0`.
  * `pay(self, amount: float) -> bool`:
    * If `amount <= 0`, prints `"Invalid payment amount."` and returns `False`.
    * If `amount > self.__balance`, prints `"Insufficient balance."` and returns `False`.
    * If `self.__spent_today + amount > self.__daily_limit`, prints `"Daily spending limit exceeded."` and returns `False`.
    * Otherwise: deducts `amount` from `__balance`, adds `amount` to `__spent_today`, prints `"Payment of ${amount:.2f} successful."`, and returns `True`.
  * `reset_daily_spent(self)`: Simulates the midnight rollover by resetting `__spent_today = 0.0`.
  * `get_balance(self) -> float`: Returns current balance.
  * `get_remaining_daily_limit(self) -> float`: Returns `__daily_limit - __spent_today`.

### Example

```text
Input:
wallet = DigitalWallet("W-881", "Priya", 5000.0, 2000.0)
wallet.pay(1200.0)
wallet.pay(1000.0)  # Exceeds daily limit (1200 + 1000 = 2200 > 2000)
print("Balance:", wallet.get_balance())
print("Remaining Limit Today:", wallet.get_remaining_daily_limit())
wallet.reset_daily_spent()  # Next day starts
wallet.pay(1000.0)
print("Balance after day 2:", wallet.get_balance())

Output:
Payment of $1200.00 successful.
Daily spending limit exceeded.
Balance: 3800.0
Remaining Limit Today: 800.0
Payment of $1000.00 successful.
Balance after day 2: 2800.0
```

### Think About

* Encapsulation manages two linked constraints (`__balance` and `__spent_today`) together in a single atomic transaction.
* Direct external manipulation of either variable would introduce invariant desynchronization.
* **Time Complexity:** $\mathcal{O}(1)$ per transaction.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 10. Patient Medical Record with Role-Based Access Audit (`MedicalRecord`)

Design a `MedicalRecord` class to manage sensitive clinical data. Clinical notes and prescriptions must only be accessed by authorized roles, and **every single view or modification must generate an immutable audit log entry**.

### Specifications

* **Attributes:**
  * `patient_id (str)`: Patient identifier (**public**).
  * `patient_name (str)`: Patient full name (**public**).
  * `__blood_group (str)`: Patient blood group (**private**, immutable).
  * `__diagnoses (list[str])`: Clinical diagnosis list (**private**).
  * `__access_log (list[str])`: System audit trail (**private**).
* **Methods:**
  * `__init__(self, patient_id: str, patient_name: str, blood_group: str)`: Initializes patient record.
  * `add_diagnosis(self, doctor_id: str, diagnosis_text: str)`: Appends diagnosis to `__diagnoses` and appends audit entry: `"ADDED: Diagnosis by Dr. {doctor_id}"`.
  * `view_record(self, accessor_id: str, role: str) -> dict | None`:
    * If `role.upper() in ["DOCTOR", "PATIENT"]`: appends audit `"READ: Accessed by {accessor_id} ({role})"`, and returns a dictionary with `"blood_group"` and a copy of `"diagnoses"`.
    * Otherwise: appends audit `"UNAUTHORIZED: Attempted by {accessor_id} ({role})"`, prints `"Access Denied: Unauthorized role."`, and returns `None`.
  * `get_audit_trail(self, admin_token: str) -> list[str]`: If `admin_token == "MED_ADMIN_SECURE"`, returns a copy of `__access_log`. Otherwise prints `"Unauthorized audit access."` and returns `[]`.

### Example

```text
Input:
record = MedicalRecord("PT-901", "Emma Watson", "O+")
record.add_diagnosis("DR-44", "Type 2 Diabetes")
record.view_record("INSURANCE-01", "INSURANCE_AGENT")  # Unauthorized role
data = record.view_record("DR-44", "DOCTOR")           # Authorized role
print("Patient Data:", data)
print("Audit Log:", record.get_audit_trail("MED_ADMIN_SECURE"))

Output:
Access Denied: Unauthorized role.
Patient Data: {'blood_group': 'O+', 'diagnoses': ['Type 2 Diabetes']}
Audit Log: ['ADDED: Diagnosis by Dr. DR-44', 'UNAUTHORIZED: Attempted by INSURANCE-01 (INSURANCE_AGENT)', 'READ: Accessed by DR-44 (DOCTOR)']
```

### Think About

* HIPAA and healthcare security laws require strict encapsulation: data cannot be read without generating an audit record.
* Direct public attribute access would bypass the audit logger completely, breaking compliance.
* Returning deep/shallow copies prevents external mutation of diagnoses and audit trails.
* **Time Complexity:** $\mathcal{O}(1)$ per read/write; $\mathcal{O}(D + L)$ for exporting records/logs.
* **Space Complexity:** $\mathcal{O}(D + L)$ where $D$ is diagnoses count and $L$ is log entries.
