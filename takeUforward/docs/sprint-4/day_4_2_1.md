# 🟢 Day 4.2.1 — Arrays: Dutch National Flag & Partitioning Practice (PBC Interview Questions)

## 1. Segregate 0s and 1s in a Binary Array

Given a binary array `nums` consisting only of `0`s and `1`s, sort the array in-place so that all `0`s appear on the left and all `1`s appear on the right. You must do this in a single pass with $\mathcal{O}(1)$ extra space.

### Example

```text
Input:  nums = [0, 1, 0, 1, 0, 0, 1, 1]
Output: [0, 0, 0, 0, 1, 1, 1, 1]

Input:  nums = [1, 1, 0]
Output: [0, 1, 1]

Input:  nums = [0, 0, 0]  # Edge Case: All identical elements
Output: [0, 0, 0]
```

### Think About

* **Two-Pointer Two-Way Partitioning:**
  * Initialize two pointers: `left = 0` and `right = n - 1`.
  * While `left < right`:
    * While `left < right` and `nums[left] == 0`: advance `left += 1` (already in place).
    * While `left < right` and `nums[right] == 1`: decrement `right -= 1` (already in place).
    * If `left < right`: swap `nums[left]` and `nums[right]`, then advance `left += 1` and decrement `right -= 1`.
* **Alternative Single-Pass Pointer:**
  * Maintain pointer `zero_idx = 0`. Iterate `i` from `0` to `n - 1`. Whenever `nums[i] == 0`, swap `nums[i]` with `nums[zero_idx]` and `zero_idx += 1`.
* **Time Complexity:** $\mathcal{O}(N)$ — Single pass traversal.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 2. Move All Negative Numbers to Beginning and Positive to End

Given an unsorted integer array `nums` containing both positive and negative values, rearrange the elements in-place such that all negative numbers appear at the beginning of the array and all positive numbers (including zero) appear at the end. The relative order of elements does not need to be preserved.

### Example

```text
Input:  nums = [-12, 11, -13, -5, 6, -7, 5, -3, -6]
Output: [-12, -6, -13, -5, -3, -7, 5, 6, 11]  # Any valid negative-first segregation

Input:  nums = [1, -2, 3, -4, 5]
Output: [-2, -4, 3, 1, 5]

Input:  nums = [-1, -2, -3]  # Edge Case: All elements already negative
Output: [-1, -2, -3]
```

### Think About

* **Two-Pointer Partition (QuickSelect / DNF variant):**
  * Set `left = 0` and `right = n - 1`.
  * While `left <= right`:
    * If `nums[left] < 0`: `left += 1` (negative is on the correct side).
    * Else if `nums[right] >= 0`: `right -= 1` (positive is on the correct side).
    * Else: swap `nums[left]` and `nums[right]`, then `left += 1` and `right -= 1`.
* **Time Complexity:** $\mathcal{O}(N)$ — Each element is examined at most once.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 3. Three-Way Partitioning Around a Given Pivot

Given an integer array `nums` and a value `pivot`, rearrange `nums` in-place such that:
1. All elements less than `pivot` appear first.
2. All elements equal to `pivot` appear in the middle.
3. All elements greater than `pivot` appear at the end.

### Example

```text
Input:  nums = [9, 12, 5, 10, 14, 3, 10], pivot = 10
Output: [9, 5, 3, 10, 10, 14, 12]  # Elements < 10 first, then 10s, then > 10

Input:  nums = [-3, 4, 3, 2], pivot = 2
Output: [-3, 2, 4, 3]

Input:  nums = [7, 7, 7], pivot = 7  # Edge Case: All elements equal to pivot
Output: [7, 7, 7]
```

### Think About

* **Generalization of Dutch National Flag:**
  * Instead of values `0`, `1`, `2`, the three groups are `< pivot`, `== pivot`, and `> pivot`.
  * Initialize three pointers: `low = 0`, `mid = 0`, `high = n - 1`.
  * While `mid <= high`:
    * If `nums[mid] < pivot`: swap `nums[low]` and `nums[mid]`, then `low += 1`, `mid += 1`.
    * Else if `nums[mid] == pivot`: `mid += 1`.
    * Else (`nums[mid] > pivot`): swap `nums[mid]` and `nums[high]`, then `high -= 1` (do not advance `mid`).
* **Time Complexity:** $\mathcal{O}(N)$ — Exactly one pass through the array.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 4. Three-Way Partitioning Around a Range [lowVal, highVal] (Amazon, Microsoft, Adobe)

Given an array `nums` and a range `[lowVal, highVal]`, rearrange the elements in-place such that:
1. All elements strictly smaller than `lowVal` appear first.
2. All elements in the range `[lowVal, highVal]` (inclusive) appear next.
3. All elements strictly greater than `highVal` appear last.

The individual elements within each of the three groups can be in any order.

### Example

```text
Input:  nums = [1, 14, 5, 20, 4, 2, 54, 20, 87, 98, 3, 1, 32], lowVal = 10, highVal = 20
Output: [1, 5, 4, 2, 1, 3, 14, 20, 20, 98, 87, 32, 54]
Explanation: Elements < 10 come first, then elements in [10, 20], then elements > 20.

Input:  nums = [1, 2, 3, 3, 4], lowVal = 1, highVal = 2
Output: [1, 2, 3, 3, 4]

Input:  nums = [5, 5, 5], lowVal = 10, highVal = 20  # Edge Case: All elements smaller than range
Output: [5, 5, 5]
```

### Think About

* **PBC Interview Application (Dutch National Flag with Ranges):**
  * This is one of the most common variations asked at Amazon and Microsoft when testing in-place 3-pointer partitioning.
  * Three pointers:
    * `low = 0`: boundary where next element `< lowVal` should go.
    * `mid = 0`: current scanning pointer.
    * `high = n - 1`: boundary where next element `> highVal` should go.
  * Iteration logic:
    * While `mid <= high`:
      * If `nums[mid] < lowVal`: swap `nums[low]` and `nums[mid]`, `low += 1`, `mid += 1`.
      * Else if `nums[mid] > highVal`: swap `nums[mid]` and `nums[high]`, `high -= 1` (recheck `nums[mid]`).
      * Else (`lowVal <= nums[mid] <= highVal`): `mid += 1`.
* **Time Complexity:** $\mathcal{O}(N)$ — Single pass in-place partition.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.

## 5. Wiggle Sort: Peak and Valley In-Place Traversal (Google, Meta, Amazon)

Given an unsorted integer array `nums`, reorder it in-place such that:
$$nums[0] \le nums[1] \ge nums[2] \le nums[3] \dots$$

In other words, odd-indexed elements must be greater than or equal to their immediate neighbors:
* For even index $i$: $nums[i] \le nums[i + 1]$
* For odd index $i$: $nums[i] \ge nums[i + 1]$

Solve this in $\mathcal{O}(N)$ time and $\mathcal{O}(1)$ auxiliary space without fully sorting the array.

### Example

```text
Input:  nums = [3, 5, 2, 1, 6, 4]
Output: [3, 5, 1, 6, 2, 4]  # 3 <= 5 >= 1 <= 6 >= 2 <= 4

Input:  nums = [6, 6, 5, 6, 3, 8]
Output: [6, 6, 5, 6, 3, 8]

Input:  nums = [1]  # Edge Case: Single element array
Output: [1]
```

### Think About

* **PBC Interview Insight (Google / Meta):**
  * Naive approach is to sort the array in $\mathcal{O}(N \log N)$ and swap adjacent pairs, but top companies expect the optimal $\mathcal{O}(N)$ single-pass greedy solution.
* **Single-Pass Greedy Local Inversion:**
  * Iterate through index $i$ from `0` to `n - 2`:
    * If $i$ is **even**: we need $nums[i] \le nums[i + 1]$. If $nums[i] > nums[i + 1]$, swap them.
    * If $i$ is **odd**: we need $nums[i] \ge nums[i + 1]$. If $nums[i] < nums[i + 1]$, swap them.
* **Why Local Swapping Preserves Previous Conditions:**
  * If $i$ is odd and we swap $nums[i]$ and $nums[i + 1]$ because $nums[i] < nums[i + 1]$, the new $nums[i]$ is guaranteed to be $\ge nums[i - 1]$ because $nums[i + 1] > nums[i] \ge nums[i - 1]$. The earlier invariant is never broken!
* **Time Complexity:** $\mathcal{O}(N)$ — Exactly one traversal through the array.
* **Space Complexity:** $\mathcal{O}(1)$ auxiliary space.
